# Contributing

Thanks for helping. This repo is small on purpose: one skill, one script, no dependencies.

## Run the checks

```bash
python3 tests/run.py
```

Python 3.9 or newer, nothing to install. Tests must stay under ten seconds and never touch the network.

## What a good contribution looks like

- **A new example storyboard.** Add `examples/<name>.json`, make `python3 scripts/storyboard.py check examples/<name>.json` pass with no errors, render it with `python3 scripts/storyboard.py render examples/<name>.json --model all --format md -o examples/<name>.md`, and add a row to `examples/README.md`. Say which model you rendered it on and what the clip looked like; do not describe results you did not see.
- **A vocabulary entry.** Edit the table in the matching `references/*.md` file. Keep the phrase short and say what it does to the shot.
- **A model limit change.** Vendors change lengths and character caps. Update `MODELS` in `scripts/storyboard.py` *and* the table in `references/model-notes.md` (a test compares them), bump `CHECKED_ON`, and put the vendor URL and the date in the PR.
- **A new model target.** Add an entry to `MODELS`, a branch in `render()`, a section in `model-notes.md`, and re-render every example (`for f in examples/*.json; do ...`).

## Rules

- No dependencies. Python 3 stdlib only. No `requirements.txt`, no `package.json`.
- No invented numbers. Every limit has a source and a date; every claim about what a model does is phrased as observed behaviour, not a benchmark.
- No personal names anywhere. The author of this repository is UniqAI <support@uniqai.app>, in commits too.
- No secrets, no `.env` files, no real API keys in examples.
- `SKILL.md` stays under 500 lines; long material goes to `references/`.
- Commit messages follow Conventional Commits: `feat:`, `fix:`, `docs:`, `data:`, `chore:`, `test:`, `ci:`.

## Deviations from org conventions

- Links inside `examples/*.md` use `utm_medium=examples` (the org list has `readme`, `readme-ru`, `skill`, `plugin`) so that referrals from rendered example pages are attributed separately from the README.
- `assets/` are generated by the maintainer-only script `scripts/_render_assets.mjs`, which imports the shared design kit by absolute path and is not part of the install. The committed SVG and PNG files are what users get.
